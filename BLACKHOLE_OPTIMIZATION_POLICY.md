# Blackhole Optimization Policy

## Goal
Keep Blackhole useful while reducing cycle burn and system complexity.

Blackhole should remain:
- a lightweight link submission board
- a place for simple community signal
- a moderated discovery surface

Blackhole should not become:
- a heavy on-chain social network
- a multi-lane ranking engine with costly live state everywhere
- an overbuilt feed that costs more than the product value it creates

## Keep
The optimized Blackhole should preserve:
- link submission
- open-link behavior
- one lightweight upvote signal
- moderation controls
- clear empty/error states

## Reduce
Optimization should focus on reducing:
- repeated board fetches
- redundant board lanes
- repeated creator-name enrichment work
- extra ranking complexity
- any feature that behaves like a full social app without strong product value

## Product direction
Preferred Blackhole shape:
- `Newest`
- `Top`
- optional curated favorites/admin picks

Avoid turning `favorites` into another expensive live-computed social lane unless there is clear value.

## Moderation rule
Do not weaken moderation during optimization.
Keep:
- delete
- soft punish
- hard ban
- clear punish

## Decision rule
If a Blackhole feature adds measurable complexity or cycle burn but does not clearly improve discovery, moderation, or community usefulness, it should be simplified or removed.
